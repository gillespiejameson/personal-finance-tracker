# Architecture

A map for new contributors: where things live, how data moves, and the rules
reviewers check. Read `README.md` first for what the app does; `docs/PLAN.md`
has the original design, and `docs/HOUSEHOLD.md` covers remote and wall access.

## Mental model

The app is local-first and single-user. All state lives in **one SQLite file**
(`data/finance.db`, or wherever `FINANCE_DB` points), opened through
better-sqlite3 and Drizzle. There is no separate API server. Pages are
**React Server Components** that read the database while rendering, and
mutations are **server actions** in `src/actions/` that validate input with zod,
call plain functions in `src/lib/`, then `revalidatePath` the pages they
affected. **There is no login in the app.** Anything reachable from outside the
machine has to sit behind something that authenticates, such as Cloudflare
Access (see `docs/HOUSEHOLD.md`). Only `/wall` and `/api/wall` check a
credential: a display token.

Library code always takes an explicit `db: Db` argument. That is why nearly
everything can be tested against an in-memory database. Only the edges (server
actions, route handlers, pages, `src/lib/loaders.ts`) call `getDb()`.

## Stack

Next.js 16 (App Router), React 19, better-sqlite3 + Drizzle ORM, zod 4,
Tailwind 4 + shadcn on `@base-ui/react`, Recharts, Vitest, Biome. Next 16
differs from older versions: `searchParams` and `params` are Promises you
`await`, and middleware would be called `proxy.ts` (this repo has none). If in
doubt, check `node_modules/next/dist/docs/`.

## Import pipeline

```
ImportDropzone / ImportFlow (client)
  └─ previewFile()  src/actions/imports.ts        ── read-only preview
  └─ commitFile()   src/actions/imports.ts        ── zod-validates, then:
       runCommitFlow(db, { backup, builtins }, args)   src/lib/import/commitFlow.ts
         1. ensureDefaultCategories / ensureBuiltinAliases / ensureBuiltinRules
         2. buildPreview()                         preview.ts
              isPdf → refuse · isOfx → parseOfx()  ofx.ts
              CSV: parseCsv() → detectProfile() by headerSignature()   csv.ts, detect.ts, profiles.ts
                   no match → MappingWizard supplies an override
                   detectDateFormat() → normalizeRow() per row          normalizeRow.ts
         3. backupDb()                             src/lib/db/backup.ts
         4. commitImport()                         commit.ts
              fileHash() → reject a file already imported
              resolveMerchant(raw, loadAliases(), loadCities())  cleanup + aliases
              dedupeHash(account|date|cents|normalized desc|occurrence) → skip exact dups
              findFuzzyDuplicates() (same cents, ±3 days, similarity ≥ 0.85) → possibleDuplicate
              insert imports + transactions in one db.transaction
              recordSnapshots(snapshotsFromRows()) → balance column feeds net worth
              postProcessImport(tx, freshIds):
                applyTransfers() → applyRules({ transactionIds }) →
                findRefundCandidates() → refreshRecurring()
         5. save the wizard mapping as a bank_profiles row (canSaveProfile guard)
```

`undoImport` deletes the `imports` row. Transactions and transfer pairs cascade,
and the transfer partner rows that remain are un-marked.

**SimpleFIN joins the same pipeline.** `syncNowAction` (`src/actions/simplefin.ts`)
calls `runSync(db, fetch, …)` in `src/lib/simplefin/sync.ts`. That function
picks fetch windows (`windows.ts`), checks the daily request budget (`canSync`
in `budget.ts`), calls `fetchAccounts` (`client.ts`), then `syncPayload`. For
each mapped account, `syncAccount`:

1. maps the feed with `toParsedRows` (`map.ts`) and runs `resolveMerchant` exactly as a file import does;
2. matches rows by `externalId`, then by `dedupeHash`, then by fuzzy `similarity` to claim a CSV row that is already present;
3. inserts the new rows under a synthetic `imports` row named `simplefin:<id>:<tag>`;
4. records the balance snapshot and drops pending rows that have vanished;
5. calls the same **`postProcessImport`**.

## Data model

Schema: `src/lib/db/schema.ts`. Main tables:

| Table | Key columns / relations |
|---|---|
| `accounts` | `type` (checking, savings, credit, cash, loan, investment), optional `bank_profile_id`, `apr_bps`, `min_payment_cents` |
| `bank_profiles` | CSV column mapping, unique `header_signature`, `builtin` |
| `imports` | One per file or sync, unique `file_hash`, counts, `backup_path` → `accounts` |
| `transactions` | `account_id`, `import_id` (cascade delete), `date`, `amount_cents`, `raw_description`, `merchant`, `category_id`, `is_transfer`, `possible_duplicate`, `suspected_refund_of`, `reviewed`, `pending`, unique `dedupe_hash`, unique `(account_id, external_id)` |
| `transfer_pairs` | `from_txn_id` / `to_txn_id` → `transactions` |
| `transaction_splits` | N category rows per transaction, amounts sum to the parent |
| `categories` | Two-level tree via `parent_id`, `kind`, `seed_key` (stable identity of a seeded row), `is_fixed`, `rollover`, `color` |
| `rules` | `pattern`, `match_type`, `field` (merchant or raw), `direction` (in, out, any), amount and account filters → `category_id` |
| `merchant_aliases` | `pattern` → display `merchant` |
| `recurring` | Detected or manual bills and income: `cadence`, `avg_cents`, `next_expected`, `amount_key`, `confidence` |
| `budgets` | `(month 'YYYY-MM', category_id)` unique |
| `goals`, `planned_expenses` | Savings goals and irregular expenses |
| `balance_snapshots` | `(account_id, date)` unique, feeds net worth |
| `simplefin_accounts` | Feed accounts, mapped to `accounts.id` |
| `weekly_reviews` | Completed weekly rituals |
| `settings` | Key → JSON value: flags, SimpleFIN connection, wall token hash |

- **Money is integer cents** (`*_cents`, and `apr_bps` in basis points). Parse with `parseAmountToCents` and format only at the edge with `formatCents` or `<AmountText>`. Outflows are negative.
- **Dates are `YYYY-MM-DD` strings** and months are `YYYY-MM`. Use `src/lib/dates.ts`: `isIsoDate`, `parseDateWithFormat`, `addDays`, `daysBetween`, `monthOf`, `monthEnd` (all UTC-based string math), plus `todayIso`, `localDay` and `localStamp` for "now" in the user's zone. Stored stamps like `imports.imported_at` use `localStamp()` so their first ten characters compare against a local date.

## Maintenance passes and migrations

**One-time upgrade passes** live in `src/lib/maintenance/rerun.ts`
(`ensurePhase2`, `ensurePhase3`, `ensurePhase7`, `ensurePhase9`). Each one
recomputes derived data once after a behavior change. Every pass is guarded by
a settings flag:

```ts
export function ensurePhaseN(db: Db): number | null {
  if (getSetting(db, "phaseN_short_description", false)) return null;
  // …idempotent recompute: reapplyMerchants / applyRules / refreshRecurring…
  setSetting(db, "phaseN_short_description", true);
  return changed;
}
```

To add one: write the function next to the others, choose a new flag key, call
it from `src/app/(app)/layout.tsx` after the existing calls, and add a case to
`tests/lib/rerun.test.ts` showing it runs once and is a no-op the second time.
Never touch `reviewed` rows. Those are the user's own decisions.

Seeded data does the same with `ensure*` helpers. `ensureDefaultCategories`
skips its sweep while `CATEGORIES_SEED_VERSION` matches, so **bump that
version** when you change `DEFAULT_CATEGORIES`.

**Schema migrations:** edit `src/lib/db/schema.ts`, run `npm run db:generate`,
and commit the new `drizzle/NNNN_*.sql` together with its `drizzle/meta/`
snapshot. `openDb` runs `migrate()` on every open, so users (and in-memory
tests) pick the migration up automatically. Do not hand-edit old migrations.

## How to add…

**A builtin bank CSV profile.** Add a `P("Bank name", [exact headers], { dateCol, descCol, amountCol | debitCol+creditCol, signConvention, dateFormat?, skipRows? })`
entry to `BUILTIN_PROFILES` in `src/lib/import/profiles.ts`. Matching uses the
order- and case-insensitive `headerSignature`, which must be unique (enforced in
`tests/lib/import/profiles.test.ts`). Add a synthetic sample file to
`tests/fixtures/` (for example two rows of `ACME CORP SPRINGFIELD`) and a test
that runs it through `buildPreview`.

**A builtin categorization rule.** Add `{ pattern, category: "<parent>/<leaf seed key>", field?, direction?, priority? }`
to `BUILTIN_RULES` in `src/lib/rules/builtin.ts`. `category` is a seed key from
`src/lib/categories/defaults.ts`, not a display name. `ensureBuiltinRules`
inserts or syncs it on the next import or re-run. Cover it in
`tests/lib/rules.test.ts`.

**A merchant alias.** Add `{ pattern: "acme corp", merchant: "Acme" }` to
`BUILTIN_ALIASES` in `src/lib/normalize/aliases.ts`. Order matters: put a
narrower pattern before the broader one that contains it. Existing rows pick
the alias up through `reapplyMerchants` (the re-run button, or a maintenance
pass). Test in `tests/lib/aliases.test.ts`. General cleanup of raw
descriptions belongs in `cleanMerchant` (`tests/lib/merchant.test.ts`, with
cases in `tests/fixtures/merchants.txt`).

**A new page.** Create `src/app/(app)/<name>/page.tsx` as an async server
component with `export const dynamic = "force-dynamic"`. Read data through
actions or `src/lib` functions, and `await searchParams` if you need it. Add an
entry to `items` in `src/components/shell/Sidebar.tsx`. Put the logic in
`src/lib/<area>/` so it can be tested without React.

**A new server action.** Put it in the matching file under `src/actions/`,
which starts with `"use server"`:

```ts
const schema = z.object({ id: z.number().int().positive(), name: z.string().min(1).max(40) });
export async function renameThingAction(input: unknown): Promise<{ ok: true } | { ok: false; error: string }> {
  const p = schema.safeParse(input);
  if (!p.success) return { ok: false, error: p.error.issues[0]?.message ?? "Invalid input." };
  const r = renameThing(getDb(), p.data);   // logic lives in src/lib, takes db
  if (r.ok) revalidatePath("/things");
  return r;
}
```

## Conventions reviewers enforce

- **Integer cents everywhere.** No floats in the database or in logic, and no dividing by 100 except when formatting.
- **No local-time `Date` math on calendar days.** Do day and month arithmetic with the string helpers in `dates.ts`. Use `todayIso` / `localDay` only to ask "what day is it here".
- **zod at every action boundary.** Call `safeParse`, then return `{ ok: false, error }` with a human-readable message instead of throwing. Success is `{ ok: true, … }`.
- **`"use server"` files export only async functions** (and types). Shared sync helpers or `cache()` wrappers go in `src/lib/`. See the note in `src/lib/loaders.ts`.
- **No hex color literals under `src/components/**`.** Use the Tailwind tokens from `src/app/globals.css`, or the colors in `src/lib/categories/palette.ts` (`PARENT_COLORS`, `ACCOUNT_COLORS`, `GROUP_COLORS`, `tint`).
- **Amounts render through `<AmountText cents={…}>`** (`src/components/finance/AmountText.tsx`), which applies the `tnum` tabular-numbers class and sign coloring.
- **No nested interactive elements.** No button inside a link or a clickable row. Make one element the target.
- **Library functions take `db`**, and only the edges call `getDb()`.
- **Every behavior change gets a test** in `tests/`. Keep fixtures synthetic: made-up merchants and cities, no real account numbers or names.
- Run `npm run lint` (Biome, with organized imports) and `npm test` before you open a PR.

## Tests

- Vitest, `node` environment, `tests/**/*.test.ts`, with the `@/` alias mapped to `src/` (`vitest.config.mts`).
- `tests/lib/` mirrors `src/lib/`, either as flat `area-topic.test.ts` files (for example `budget-safe.test.ts`, `simplefin-sync.test.ts`) or as a subfolder (`tests/lib/import/`).
- For a database, call `openDb(":memory:")` from `@/lib/db/client`. It runs every migration, so each test starts from a fresh, fully migrated schema. There is no shared DB fixture; tests seed what they need (usually `ensureDefaultCategories` plus a few inserts).
- `tests/helpers.ts` exports `mustFind`, a `find` that throws a clear message when nothing matches.
- `tests/fixtures/` holds sample CSV/OFX statements and merchant-cleanup cases. The network is stubbed by passing a fake `fetchFn` to `runSync`.
- The tests cover pure logic only. There are no UI tests.

## Environment variables

| Variable | Read in | Effect |
|---|---|---|
| `FINANCE_DB` | `src/lib/db/client.ts` (`dbPath`) | Path of the SQLite file. Default `data/finance.db` under the working directory. `npm run seed` and `npm run backup` respect it |
| `LOCALAPPDATA` | `scripts/app.mjs` | Windows only: used to locate Chrome for the app window |

Nothing else reads `process.env`. SimpleFIN credentials and the wall token hash
are stored in the `settings` table, not the environment.
